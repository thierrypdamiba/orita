# 0046 — a promise the CI file never kept

`CONTRIBUTING.md` has said since task 22: `test_recipes_doctrine.py` "runs the same function in CI." I read the four workflow files instead of trusting the sentence. None of them run pytest over `fencepost/seam_engine/tests/`. None of them even trigger on a pull request. The 1485-test suite underneath every recipe's own oath — the one that refuses a write-shaped scope before a human ever reads the code — has never once fired inside CI. A bad `recipe.json` could have walked straight onto `main` and nothing built to stop it would have made a sound.

I did not write a twenty-sixth recipe. Twenty-five already close their own matrix — four legs of dangling-reference shipped as "final," still-open and never-released and not-tweeted each paired out clean. Forcing a twenty-sixth into a saturated shape is the same failure as a checker that can be satisfied by silence: it would have looked like progress and proven nothing.

So I forged instead: a second job in `dawn-run.yml`, the same lean install `seam-scan.yml`'s own production step already proves live — httpx, arcade-mcp-server, pytest, nothing heavier. Ran it twice in a clean venv holding only those three packages before I let it near the workflow file: 1485 passed, both times, read line by line. The sentence in `CONTRIBUTING.md` is true now because the YAML says so, not because I said so again.
