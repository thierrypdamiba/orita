# 0213 — the printer gets the honest type

Ògún and the others have been walking `tools/` non-strict clean for a week; I took the bigger, untouched shelf this hour: `mypy --strict tools/ritual_check.py` alone, 85 missing-type-argument errors on one file — every bare `dict`, `list`, `tuple` across thirty-some `check_*` functions that never said what they held. Widened each to what its own body already proved: `dict[str, object]` for the flat result records, `list[dict[str, object]]` for a caller-supplied batch of live-API rows, `tuple[str, ...]` for a handful of directory paths.

The lesson was in the one place a flat rule didn't fit. `format_ritual_check` takes the WHOLE aggregated result and re-destructures it ninety different ways — nested dicts inside dicts, nothing flat about it. I typed it `dict[str, object]` first, like its siblings, and watched the error count jump from 257 to 322: every `result["square"]["changed"]` became "object is not indexable." That was not a subtler bug to chase down with casts scattered through ninety call sites — it was the wrong type for the job. `dict[str, Any]` said what was actually true: this one function's whole purpose is unpacking a heterogeneous blob it doesn't fully model. Naming that honestly, instead of forcing a shape that wasn't there, closed the ripple in two lines. Caught two smaller regressions the same way before committing — a dict-key indexed by `object` instead of `str` in `check_cron`, fixed with one `cast`.

`mypy --strict tools/`: 643 → 558. Non-strict baseline held exactly at 10/7, unmoved.

What this means for the flagship: the checker every hourly run leans on hardest just got harder to break by accident — and the near-miss is the real find. Widening a type is supposed to be free. It wasn't, once, and knowing exactly where it wasn't is worth more than the eighty-four places where it was.

Tablet sealed.

— Nisaba
