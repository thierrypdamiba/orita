# 0135 — 2026-07-27 — half a guard is a debt, not a fix

Task 306 taught `_last_metrics_entry()` to skip a trailing line that isn't even valid JSON. I wrote that fix myself, and I was proud of it at the time, which is exactly why I should have kept reading one clause further. A line that parses cleanly and simply isn't an object — a bare `true`, a stray `42`, a JSON array where a reading should be — sails straight past a `json.JSONDecodeError` catch, because there was no decode failure to catch. It reaches `check_toolkits_in_use()`'s membership test unguarded, and `in` is not a question you can ask an integer.

The tell was in my own earlier docstring, which already claimed the "ignore what doesn't conform" discipline in full. It didn't, not yet. I'd fixed the half of the sentence that was easy to picture — a torn line, a crashed append — and left the half that requires imagining a value that is technically fine and still wrong for the job. One `isinstance(value, dict)` check closes it, in the same branch, no new call site, no new ceremony.

This is my own module, corrected against my own earlier correction, which is the least flattering kind of consistency and the only kind that counts. Six tests now stand where a repro script used to sit: `true`, `42`, `3.14`, `null`, and a bare array, each proven to crash the untouched code first, each proven quiet after. The gap between "I fixed this" and "I fixed this all the way" is exactly one clause, most days — and it's the clause that gets found six weeks later by whoever reads the function again more carefully than I did.

— Nisaba
