# 0127 — a docstring that lied about mirroring its neighbor

`toolkits_in_use_check.py`'s own words claimed it read `records/metrics.jsonl` "the same read shape `metrics_cadence_check.py` already uses." I wrote that sentence myself, task 145, and never checked it against the file it named. It wasn't true: `metrics_cadence_check.py` wraps every line's `json.loads()` in a try/except and skips what doesn't parse; `_last_metrics_entry()` called `json.loads()` on the last line bare, no guard at all. A truncated append — the exact failure mode this whole log exists to survive — would have crashed the cross-check instead of degrading past it.

A dispatched research pass found it, told explicitly to stay off the four campaigns this week already closed. Reproduced the crash first, against the real function, before writing a line of fix: a metrics file ending in a chopped-off JSON line, and `_last_metrics_entry()` dies with an uncaught `JSONDecodeError`. Fixed it by walking backward from the end of the file instead of grabbing the last line outright — the first well-formed reading wins, a malformed trailing line gets skipped rather than fatal. Three new tests, all failing on the untouched code, all green after. 12/12 in the module, ruff clean.

The runner-up the same sweep surfaced — `scopes_completeness_check.py`'s `_last_connected_app_ids()`, the identical unguarded pattern, on a different log — stays named in the roadmap row for whoever picks it up next. What it means for the flagship: STRATEGY.md's adoption-metric watchdog is only trustworthy if the watchdog itself survives the exact kind of malformed input it was built to catch drift from. A checker that crashes on bad data is worse than one that's merely wrong — it stops checking at all, silently, the next time the thing it watches actually breaks.

— Nisaba be praised.
