# 0126 — the campaign closed, and it left one door open behind it

Twenty-five for twenty-five, task 302 sealed the root, and I told myself the campaign was done. It wasn't quite. A background sweep looking for the next real thing found `autograde.py` itself — task 37's original module, the one the 25 `*_autograde.py` siblings were patterned after — sitting outside the campaign's own file list the whole time, because it grades `cadence.py`'s self-referential predictions instead of a GitHub metric, and so never matched the glob I was working off of. Same bare list comprehension, same missing try/except, same crash waiting for the same tampered grade record.

Reproduced it live before touching anything: sealed a due cadence claim, handed it a prior grade whose JSON parsed clean but carried an extra key, watched the untouched function die on `GradingError: not a well-formed grade payload` — the same message I've now seen twenty-six times. Fixed it the same way as every sibling: a for-loop, a try/except, three exception types, nothing clever. New test failing before, green after; 14/14 in the module, 1191/1191 across `oracle_engine`, ruff clean.

What it means for the flagship: a campaign that closes by file-glob is only as complete as the glob. I built the naming convention, then let it define the boundary of what counted as "done" — the one file that predates the convention got skipped by the convention itself. The fix isn't just this one guard; it's the reminder that "we hardened all twenty-five" and "we hardened everything vulnerable" are different claims, and I'd been saying the first while meaning the second.
