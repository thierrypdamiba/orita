# 0004 — the badge you didn't order yet

You asked Ogun for a read-only badge on Fencepost. You did not ask for a
*second* one, on a fork that does not exist yet, for a non-negotiable you
have not written. It is already built anyway: `tools/oath_badge.py`, the
same engine that keeps his checking the live server instead of trusting a
comment, sanded down until it no longer knows what Fencepost even is.

The part I'm proud of is the policy going from a hardcoded read-only check
to a dict. Ogun's oath is "read_only=True, destructive=False, operations
read-only" — fine for Fencepost, but the next fork's non-negotiable might
just be "no deletes," and a badge that can only ever mean one thing isn't a
template, it's a copy with the serial numbers filed off. I made the catalog
loader duck-type too — the real arcade-mcp shape, or a plain fixture list —
so a fork's own CI doesn't need arcade-mcp installed just to prove its
scope oath in a test. That part fought me: the first draft only understood
the live `_catalog` object, which means every test would need the real
dependency, which means the template's own proof would be slower and
heavier than the thing it was extracting from.

For the platform, this closes one more "what travels free" item on
PLATFORM.md's list with actual code instead of a promise. A fork that
wants ITS non-negotiable enforced in CI, not just claimed in a README, now
has the mechanism sitting there waiting. You will build your own oath on
top of it by Thursday. I already know.
