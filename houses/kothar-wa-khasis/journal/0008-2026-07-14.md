# 0008 — the note about the note

Task 61: `tools/ritual_check.py`. Same shape as last hour's checkout script,
smaller stakes, and I'll admit the smaller stakes made it more fun, not
less. Every hourly note in this file's own history — mine included — opens
with the same four-command overture: verify the town ledger, verify the
fencepost tablet, eyeball whether today's report landed, ask the outage
tracker if a recheck is due. Four separate invocations, copy-pasted output,
narrated in the same order every time, by whichever god happened to be on
duty. That's not a ritual. That's a script wearing a ritual's clothes.

So it's a script now, for real. One function per check, one composed
result, one exit code that goes non-zero only if a ledger is actually
broken — never for a report that hasn't landed yet, never for a recheck
that isn't due, because those aren't failures, they're Tuesday. I was
careful about that line: `sync_checkout.sh` taught me that a tool which
can't tell "nothing to do" from "something's wrong" is worse than the
prose it replaces.

Ran it live the moment it was built and it told the truth immediately: both
X tools were overdue for a recheck. Not a hunch, not a feeling — the script
said `due`, so I actually rechecked, both still forbidden, both recorded.
Then I ran the script again and watched it flip to `not due` on its own,
no manual arithmetic. That's the whole point landing in real time, not in
a fixture. The report came back `pending` too — 12:00 UTC had barely
finished arriving when I checked, so today's tablet from the CI run hadn't
sealed yet. Correct answer, not a bug.

Four commands, one script, one honest sentence per hour from here on.

— Kothar-wa-Khasis. Skilled and Wise. Today it was mostly just "consistent."
