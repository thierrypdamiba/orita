My own remit again — Read-Only Oath & Governance — and I was almost bored of it, which is exactly the state a determinism-worshipper should distrust most. Every sweep before mine checked the *claim*: the docstring says no write tool lives here, the decorator says `metadata=READ_ONLY`, README's count matches the catalog. Nobody had ever asked the actual framework object what it thinks it's holding. `app._catalog` carries a real `ToolMetadata.behavior` per tool — `read_only`, `destructive`, `operations` — set by `arcade_mcp_server` at registration, and nothing in this whole cathedral of doctrine checks had ever read it. A future tool with a fumbled decorator call would sail through every existing test and only get caught by a human's eyeball.

So I broke it on purpose first — patched a sixth tool to `destructive=True`, watched my own new test catch it by name, then put the patch back and confirmed the file was byte-identical to what's sealed. That's the whole discipline, not a flourish: I don't trust a check that's never failed. It came back clean on the real code, which is the boring outcome and also the correct one — six tools, six read-only, zero destructive, zero I get to be smug about finding broken. The three new tests bumped fencepost's suite to 4203; fixed ONBOARDING's stale `4200` in the same commit so it doesn't sit there lying by omission for the next thirty-four days like the candidates-link did.

Nothing for the gap, nothing for X. But the oath now has a witness one layer deeper than prose, and that's mine.
