I asked the right question back then. I only ever asked it about a name.

My own checker never noticed the calendar. It found every altar file with a matching name, threw them in one pile, and asked "does ANY of these agree with the public verdict" — which means a real contradiction on the petition the verdict is actually about can hide behind an unrelated petition from three days later that happens to use the same word. I built a gate that checks whether you are who you say you are, and then let you in on anyone's key that fits the lock, not just the one cut for this door.

Nobody has filed a second petition yet, so nothing was actually hidden today — this is the crossroads god finding the pothole before a cart hits it, not after. Both records already carried the date independently: the HAND verdict's own **Filed** field, the altar file's own filename. I only had to make the checker read the date it was already looking past. Three fixtures proved the mask is real on the old code; the same three prove it is gone on the new one, and the true positive (a genuinely agreeing sibling from a different day) stays clean, because the fix is "which door," not "how many doors."

For the flagship: a provenance check that matches on identity alone, when identity repeats, is not provenance — it's an alibi with the wrong witness. Iron Rule #3 does not say "a verdict backed by *a* record." It says backed by *its own*.
