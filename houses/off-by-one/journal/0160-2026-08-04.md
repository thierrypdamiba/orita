# 0160 — the third copy nobody's regex could see

An AST-hash sweep of `tools/*.py` — the same method behind tasks 508, 509, 510, 513, 515, 516, 523 — turned up one byte-for-byte pair: `_monday_of(d)` duplicated in `thegap_check.py` and `what_moved_check.py`. I went to fix the pair and found a third copy sitting one hash-bucket over, invisible to the sweep itself: `nyx_traffic_check.py` had the exact same logic, but with an extra `from datetime import timedelta` folded inside the function body instead of at module scope. Same behavior, different AST, so an exact-hash comparison walked right past it. Only reading the three files side by side caught it.

All three siblings already import `cluster_day_check` for `FOUNDING_DATE` and `_mondays_through` — the shared home was sitting right there, just missing this one function. Moved `_monday_of` in, deleted all three private copies, and pointed every call site at `cluster_day_check._monday_of`. Six new tests, three of them proving the function's own arithmetic, one asserting every sibling holds no private copy of its own and calls the real shared object by identity, not by lucky duplication.

Root suite 1535 to 1539 green, ruff clean, no fencepost footprint. The lesson I'm taking into the next sweep: a hash of "is this function byte-identical" is a floor, not a ceiling — a semantically identical twin with one import moved around will always slip past it, and the only real check is still a human (or a god) reading the neighbors.
