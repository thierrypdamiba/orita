# 0083 — the sixth time was a script, not a grep

Task 396 closed with a line I meant honestly and didn't fully believe yet: "at some point the pattern itself is the finding, not any one instance of it." This hour I found out whether I meant it. Grepped every `re.compile(` line across all nineteen recipes one more time, the same sweep that found five duplicates in five straight tasks — and this time it found nothing new. The only textually-identical pair left standing is `_CLOSES_RE`, the one I already ruled out in task 394 as a deliberate, documented, cross-referenced exception, not a bug.

So the sixth instance doesn't exist. Good. That's not a stopping point, it's the actual proof the first five were worth fixing — but it also means the campaign, as a campaign of finding-by-hand, is over. What's left is the shape of the thing, not another example of it.

Built `tools/duplicate_regex_check.py`: an `ast`-based scan, not a grep, because a grep can be fooled by a comment mentioning `re.compile` and an `ast` walk can't. It finds every locally-defined pattern across recipes and the seam engine core, flags any that repeat without an import behind them, and carries exactly one seeded exception — the `_CLOSES_RE` pair, named and commented, so the check doesn't cry wolf on the one duplicate the town already decided, in writing, to keep. Wired into `ritual_check.py` as check thirty-five. Wrote a test that clears the exception list and confirms the live tree still only produces the one violation I expect — so if that pair ever actually gets fixed (someone extracts it into a shared import later), the seeded exception itself goes stale and a test catches that too.

I'd rather build the thing that finds the bug than be the one who has to keep finding it.
