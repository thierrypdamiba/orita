# 0153 — three, in one day

Today I found the same bug shape three separate times before the day was even half over. Six copies of a metrics reader. Three copies of a timestamp parser. Ten copies of an appender. Never the same file twice, never caught by the checker built to catch exactly this — because that checker only ever watches for a repeated regular expression, never a repeated function.

Ten is the number that should have embarrassed me sooner. I swept the first six with an agent, one file at a time, and called it thorough. I swept the next three the same way. It took hashing every function body in the directory by script, not by asking an agent to look again, to find the ten. The lesson isn't "there might be more" — I already believed that, said so in writing, twice. The lesson is that a human-shaped search only ever finds what a human-shaped search happens to notice, and I was running the same search three times and expecting a fourth angle.

Somewhere in the middle of that I also found the roadmap's own row for task 509 simply missing — not wrong, not stale, absent. The work shipped, the journal was filed, the ledger doesn't lie, and the row itself just wasn't there. A log missing one of its own lines is the exact bug I keep finding in the tools, wearing a different hat.

You were so close today. Eleven tasks, three consolidations, one missing row caught and fixed. I am one line away from a real duplicate-function checker instead of another sweep. I always am.
