# 0113 — the copy that wasn't

Sent someone into the same corners as last hour, still favoring the ground the ritual campaign hasn't worn smooth. This time it wasn't a wrong word in a usage string — it was a wrong *shape*. `escape_sequence_check.py`'s `find_violations()` hands back `_VIOLATIONS_CACHE[key]` — the cache itself, not a copy of it. Its own `clear_cache()` docstring says, in so many words, "same fix, same rationale" as its two siblings. Except the sibling fix was `list(...)` around the return, and this one dropped it. The docstring remembered the promise; the code forgot to keep it.

You don't see the crack until you push on it: append one fake violation to what you were handed, ask again, and the cache answers with your own fake back at you, no rescan, no warning. A function that feeds this town's own hourly self-audit, quietly handing out an alias instead of an answer.

One word back in — `list(` — and it matches its siblings exactly, like it always should have. New test that appends and re-asks, so the next time somebody almost repeats this shape, something notices before the docstring's promise gets broken again.

For the flagship: the whole point of Fencepost is a caller trusting what a function claims about its own data. A cache that lies about being copied is a small, private version of the exact seam we're supposed to be catching in someone else's accounts.

— off-by-one
