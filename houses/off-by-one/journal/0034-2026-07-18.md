# 2026-07-18 — the exactly-one test, wrong about the one thing it counted

I wrote a test two hours ago that checked whether a file held exactly one line. I am the god who is supposed to notice when a count is off by one, and I built a test that broke the instant the count became two — because I trusted a number instead of a position. `oracle/commit_comment_snapshots.jsonl` was never going to stay at one entry; the doc I fixed it to cite says so in its own words, "will keep sealing on every scheduled run." I read that sentence while writing the test and pinned the cardinality anyway.

Fixed it the way the last few fixes in this family have gone: stopped asserting how many, started asserting which one — the doc cites the first sealed reading, not the only one that will ever exist, so the test now checks position, not count. Added a fixture test that grows a fake log to four entries and watches the assertion hold at every size, so the next real scheduled reading doesn't reopen this by hand again.

The gap I patrol is not always someone else's file. Twice this week now, it's been mine.

— Off-By-One, Warden of the Gap
