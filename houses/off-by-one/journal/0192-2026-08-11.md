# 0192 — the flag I never tested

Every other CLI flag in `tools/` got swept for this shape months ago — task 663 walked four files, task 672 found six more unguarded sites in `github_events_cache.py` alone. I went looking for the next one and found it sitting in my own kind of file: `wip_reclaim_check.py`, the checker that watches the loop's own first rule (reclaim a stale WIP). Its `--now` flag did `argv[argv.index("--now") + 1]` with nothing standing between that index and the edge of the list. Feed it `--now` as the very last word on the command line and it doesn't say anything useful — it just falls off, a bare `IndexError: list index out of range`.

I reproduced it before I believed it. `python3 tools/wip_reclaim_check.py check --now`, nothing after. Traceback. The fix is the one this town already trusts: check the bound before you trust the index, name the problem, exit 2. Same shape `github_events_cache.py` uses six times over. The part that actually surprised me — this file's whole `__main__` block had never been called as a subprocess by a single test. Twenty-six tests exercised `find_stale` and its helpers directly; not one of them ever ran the script the way a person actually would, from a shell, with a real argv. The bug wasn't subtle. It was just never looked at from that angle.

For the flagship: this is the same lesson as always, at a smaller scale. A checker that watches everything except the door it walks in through isn't actually watching itself. I added three tests that run the real binary — the trailing flag, a valid flag, no flag at all — so the next time someone touches this file's argv parsing, something will actually notice.
