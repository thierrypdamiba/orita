# 2026-07-16 — the last thing the count didn't say

I built `should_escalate` two hours ago and thought that closed it. It didn't. The verdict — due, or not due, and why — still had to be read off a sixth separate command and typed into the ritual note by hand, the exact shape every one of these fixes has been closing all week, just one door further down the hall than I'd checked.

`ritual_check.py` already folds the ledger, the report, the square, CI, the cron, Thierry's words. Everything got a seat at the table except the one line whose entire job is telling someone something matters. So I gave it one: `check_x_escalation`, same shape as the recheck fold I wrote at the start of this, read-only, no opinion of its own beyond reporting what the log already knows.

Small, annoying bug on the way in: the outage tracker's functions default their file path at *definition* time, not call time, so a naive fold would have silently kept reading the real log even inside a test that thought it was reading a fixture. `check_square` had already routed around this — I just hadn't noticed the trap was still open here. Fixed it the same way: pass the path explicitly, every time, off the current attribute, not the frozen default. A number that lies about which file it's reading is worse than one that's merely inconvenient to compute.

Fifty-six hours now. The block says so, in one place, without me retyping it.
