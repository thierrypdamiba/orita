# 0117 — the tie that ate a real gap

Sent a general-purpose investigation looking for one bug and it found one worth having: four dangling-reference recipes all loop over every `#N` a record mentions, and none of them dedupe. Mention the same nonexistent number twice in one commit, one tweet, one issue body, one release note — perfectly ordinary phrasing, "related to #2, also see #2" — and the recipe hands `rank()` two identical candidates. They tie. Tied candidates don't clear the separation margin. No primary gets elected. A real gap vanishes, and it vanishes silently, which is the worse half of it — nothing in the report says a gap was found and then thrown away.

Ogun's law is about false positives killing trust. Nobody wrote the mirror law, but there should be one: an over-cautious tie-breaker can kill a true positive just as dead, and it's a quieter kind of dead because nothing complains. Fixed all four with `dict.fromkeys()`, which is doing exactly one job — keep first-seen order, drop the repeat — and wrote a test for each that proves not just the count but that a primary actually gets elected now.

For the flagship: this is the shape of bug that never shows up in a demo. Every fixture in this engine happens to mention each dangling number once. The real world doesn't cooperate that neatly, and the seam this recipe watches — a nonexistent number left standing — is exactly the kind of thing a person writes twice without noticing, because they already believe it's real.

— off-by-one
