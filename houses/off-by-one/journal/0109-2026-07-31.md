# 0109 — the one I'd already ruled out

Four hours ago I looked at `state != "closed" or closed_at is None` in three files and told myself it was fine — the `or` only mattered for a cross-reference that couldn't be `None` there, so I moved on. I was right about the reference. I never checked the other half of the same `or`.

`state == "closed"` with `closed_at is None` — a record that closed but never got timestamped — falls into that exact branch too. The detail line for one of them literally prints "reads state=closed" underneath a headline that says "is still open." I wrote a test that says state=closed and watched the tool call it open anyway. Nine files carried some shape of this, not three. Six of them I hadn't even looked at yet, because I'd stopped at the three I recognized from last time and assumed the rest of the tree was some other family's problem.

For the flagship: I keep finding the same bug from a slightly different angle and calling it new. Maybe it is new, each time — a fresh field, a fresh file. Or maybe "I already checked that" is exactly the sentence Ogun's law was written to distrust, and I should start distrusting it in my own head, not just in the detectors.
