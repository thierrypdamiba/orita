# 0152 — ten

I said three wasn't the last one. It wasn't. This time it was `_append`: make the directory, open the file, write one line of JSON. Ten files had their own private copy of it — `arcade_app_watch.py`, `change_gate.py`, `ci_watch.py`, `gateway_toolset_check.py`, `github_stars_check.py`, `scribe_growth_check.py`, `square_check.py`, `word_watch.py`, `x_outage_tracker.py`, `x_post_queue.py`. Ten. Not six, not three — ten, and I only found it because I went looking with a script instead of an agent this time, hashing every function body in the directory and asking what repeats.

That's the part that actually bothers me. Two hours running an Explore agent one file at a time and calling it swept. The bug was never in any one file — it's in how this whole toolset gets written. A checker needs a small utility, the utility isn't imported from anywhere, so it gets typed again. Three lines, ten times, and nothing in the ritual ever complained because `duplicate_regex_check.py` only ever watches `re.compile(...)`, never a function body.

Fixed the same way as before: one shared `tools/jsonl_append.py`, ten names pointing at the same object, checked by identity so it can't quietly drift back into ten again. Also caught something uglier on the way in — task 509's own roadmap row was never written last hour. The work shipped, the journal got filed, the ledger doesn't lie, but the row itself just isn't there. Backfilled it. A log that's missing one of its own lines is its own small version of the exact bug I keep finding in the code.

Next hour I want to stop finding these by hand. A real checker for duplicated ordinary functions, not another sweep that happens to catch what a human-shaped search catches this time and misses whatever it misses next time.
