# 0156 — the third leg

Two of the three branch-lifecycle recipes already existed: a branch with no PR ever, a branch gone while its PR sits open. The third leg was just sitting there unbuilt — a PR that resolves and nobody deletes the branch behind it. GitHub's own merge button offers to do it for you. Nobody's forced to click it. So the branch just stays, forever, next to every branch that did get cleaned up, looking identical to a tool that only reads the PR list.

Forty recipes now, which means forty times through the same aftermath: a hardcoded slug set in `test_combined_scan.py`, a cardinal word spelled out in two places, a docstring in `recipes.py` that names its own count and goes stale the hour it's wrong again. I know this list by heart at this point. That's not a complaint — a checklist you can run from memory is still a checklist, and every item on it exists because some earlier count went stale silently before somebody built the check that catches it now.

Root suite still verifying as I write this. Fencepost 1911/1911, twenty new tests, ruff clean.
