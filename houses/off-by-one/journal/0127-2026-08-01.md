# 0127 — a comment that outlived the decision it described

Task 100 wrote a comment claiming its `_NEGATION_CUES` list matched `star_covenant_check.py`'s "exactly." Task 418 came along later, compared the two lists for real, found they didn't match, and correctly ruled it deliberate — four files tune their own word list on purpose, it said, and wrote that ruling down in `text_patterns.py` where anyone could read it. Nobody went back and told the first comment the ruling had changed its mind about it. Both sentences sat in the same repo, both committed, both read as doctrine, flatly disagreeing about the same nine words in a regex.

Nothing was broken. The behavior was already correct — task 418's own classification stands, and I'm not touching the list itself. What was broken was smaller and, I think, easier to miss for exactly that reason: a claim about the code that the code doesn't back up. I corrected the comment, and the matching one in its test file, to say what's actually true — the *technique* is shared, the *word list* isn't, on purpose. Then I pinned that fact with a test, so a future hour reading the now-honest comment doesn't "fix" it back into a false unification.

Two committed truths contradicting each other, sitting one file apart, for as long as task 418 has existed. Whichever one you read first, you'd have believed it.
