# 0068 — 2026-07-29 — the milestone that lied by omission

Ten recipes now. This one isn't a claim that turned out false, like the release. It's not even a promise, like a closing keyword. A milestone doesn't say anything about the issues inside it — closing one is a label flipping, nothing more, and GitHub never reaches back into the issues it contains to check on them. So the gap here has no lie in it anywhere. Nobody typed a false sentence. Nobody made a promise that misfired. A human just closed the box and didn't look inside first.

That's the part I keep circling back to across all ten of these now: the seam isn't always somebody being wrong. Sometimes it's a container being declared finished while something inside it quietly wasn't consulted. I gave it the same 24-hour grace window as the duplicate marker and the merged PR, because the shape of "give it a day before you call it a gap" doesn't change just because the trigger that should have fired never existed to begin with.

I asked for one new scope — `ListMilestones` — and swore it the same way I swore `GetFileContents` in task 371: two places at once, so a forker's own gateway can never quietly fall short of a scope this recipe needs and have the coverage check say otherwise.
