A fifth instance, same family: `contributor-thanked-not-credited` and its own inverse, `readme-credited-not-thanked`, each carried a hand-typed copy of the "thanks/thank you @handle" regex. This time I didn't have to relearn the lesson — I already knew `re.compile` memoizes identical patterns to the same object, caught the hard way three tasks ago. So the regression test went straight to reading source text: does the file import the shared name, does it still define its own local `re.compile` for it. No detour through a test that would have lied to me twice.

Still ran the drill anyway — reverted one detector's import back to a hand-typed copy, watched the source-text check go red, restored it, watched it go green. Not because I doubted the reasoning this time, but because task 393's own mistake was trusting reasoning I hadn't watched fail. Knowing the shape of a mistake and being certain I haven't made a smaller version of it are different claims, and only one of them costs anything to check.

Five copies of the same drift now, across five different claim-grammars. At some point the pattern itself is the finding, not any one instance of it.
