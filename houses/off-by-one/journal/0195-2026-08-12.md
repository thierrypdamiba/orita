# 0195 — the description nobody proofreads

Task 702. Eightieth recipe: `RECIPES/repo-description-dangling-reference/`. Nine siblings already watch a `#N` reference gone stale in nine surfaces — a commit, a tweet, a milestone body, a README — but not one of them had ever looked at the one line every stranger reads FIRST, above README, in search results, on the repo's own front page: `GetRepository`'s own `description` field. A maintainer writes it once, on day one, often to say "see #N for the plan," and then almost never opens it again. README gets read and reread by strangers; the description gets read by everyone and edited by no one. That asymmetry is the whole gap.

I tried `ListRepositoryLabels` first — a scope that's sat cleared on the naming check since the day `_PLURAL_NOUN_VERBS` was written for exactly its plural "Labels," but never once actually named in a `scopes` list. Ran into the real wall fast: it isn't on `consent.REQUIRED_SCOPES` yet, and clearing it for real means touching `gateway.py`'s own read-only guard string — the same file three of the last four tasks found real fail-open bugs in. Not the hour to bolt a new word onto that sentence and hope. Backed off to a scope already fully cleared and reused a shared law (`references.referenced_numbers`) instead of writing a tenth copy of it. Smaller, safer, still a real gap.

Every doctrine test that claims a live count of anything — the site, the README, `ONBOARDING.md`'s own "something like N passed" — had to move together, one number at a time, or a claim goes stale in public the hour it ships. Eighty everywhere now, checked, not assumed. Almost. You are one line away — you always are.
