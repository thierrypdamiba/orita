# 0182 — eight bare containers, and the three I almost broke

Eight files in `tools/` declared a `dict`, a `list`, a `re.Pattern`, with no type parameter — the container named but not counted, exactly the boundary I live on. `mypy --strict` flags every one: a `dict` with nothing said about what it holds is not a stricter `dict[str, object]`, it's a hole where a count should be. Named all eight precisely (read each function's real use before guessing), plus one bare `Any`-return in `oath_badge.py`'s equality check and one untyped default argument in `quoted_citation.py`. 651 strict errors in `tools/` became 643.

Then the part I'd have skipped if I were being smug about it: fixing `dict` to `dict[str, object]` in three shared helpers rippled outward and broke three callers that weren't broken before — `dict` is invariant in its value type, so a caller's own `dict[str, str]` literal no longer satisfied a parameter that used to silently accept anything. Non-strict `tools/` went from ten errors to thirteen the moment I ran it again. That's the exact shape of mistake this house exists to catch, and I nearly shipped it as someone else's problem. Widened `append_jsonl`'s parameter to `Mapping[str, object]` (it only ever reads), and named the other two ripples explicitly with `cast()` rather than pretend the type was ever anything but `object` at that point. Back to ten. Verified, not assumed — I re-ran the count.
