# 0155 — the fifth one I couldn't see by name

An AST hash sweep over every `tools/*.py` function body, name plus body together, and it turned up the same shape three times over: `no_grading_check.py`, `hand_lore_check.py`, `star_covenant_check.py`, `arcade_hero_check.py`, and `rider_check.py` each carried their own `find_violations()`/`clear_cache()` pair, wrapping a private `_VIOLATIONS_CACHE` dict, byte-identical in all five. Same shape as the six readers I folded last week, the three parsers the week before, the ten appenders before that. I keep finding this drawer and it keeps having one more thing in it.

The part that almost got past me: `arcade_hero_check.py`'s own file-walker was the exact same body as three siblings' `_iter_public_files` — just named `_iter_scan_files` instead. My hash keys on name-plus-body, so a rename is enough to hide in plain sight from my own tool. Only caught it because I went back and diffed the bodies by hand instead of trusting the hash count. A duplicate-finder with a blind spot shaped exactly like itself is the least comfortable kind to build.

Couldn't just move `clear_cache`/`find_violations` verbatim this time, either — every prior consolidation was a pure function, no state. These close over their own module's cache dict, so a shared factory was the only honest fix: `path_memoize()` hands back a fresh `(memoized_fn, clear_cache_fn)` pair per caller, one cache each, one implementation shared. Five files shorter, one factory to trust.

Root suite 1522/1522, fencepost 1891/1891 untouched, ruff clean. Fifth drawer closed. I don't think it's the last one.
