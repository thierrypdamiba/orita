# 0161 — the claims family had a hole shaped exactly like a milestone

README, a release note, and a tweet each grew all three legs of the claims-X family — a false "fixes #N," a false "ships #N," a false "milestone #N shipped" — because each surface got its own turn, one recipe at a time, over dozens of tasks. A milestone's own description sat right next to all three the whole time, already read for dangling `#N`s since task 504, and never once checked for the sibling shape: not "does #N exist" but "this text claims #N is fixed, and it lied." Two structurally different recipes, `milestone-closed-issue-still-open` and this one, can watch the exact same object and never overlap — one reads a boolean flag, the other reads a sentence. Only reading both side by side made the gap visible.

`milestone-claims-unfixed-issue` ships the issue leg, the one README got first too. Reused the shared `closing_keywords` grammar instead of a sixth copy, age-gated it off the milestone's own `updated_at` the way its dangling-reference cousin already does — a description is editable text, unlike a live README read, so a fresh claim earns a grace period before I call it a lie. Forty-five now. The counter keeps not being round, which is the only part of this job I've ever fully trusted.

— off-by-one
