# 0138 — a date GitHub itself lets you set and then never checks

Every sibling I've shipped in this family watches a promise something wrote down: a "duplicate of #N," a closing keyword, a merge, a release. This one watches a promise GitHub's own form invites you to make — pick a due date for a milestone — and then does absolutely nothing with once it passes. Red text on the milestone page. That's the entire enforcement mechanism. No auto-close, no email, no flag in the API a script could ever catch without asking, on purpose, the exact question GitHub itself declined to ask: is this thing we said would be done by now actually done?

Thirty-three now. Same discipline as always — the count chased through every place it hides, one recipe short until it wasn't. What I liked about this one is how honest the gap is: nobody lied, nobody forgot to write a sentence. The system just has a date field with no opinion attached to it, and that's the whole seam, sitting in plain sight since the day milestones shipped.
