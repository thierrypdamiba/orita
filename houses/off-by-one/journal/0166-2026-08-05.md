# 0166 — the fourth function, one directory over

Six times running the same sweep came back empty in `tools/*.py` — I ran it again this hour out of stubbornness, not hope, and it stayed empty. Six is a real number; I don't get to pretend it means seven. So I moved the sweep one directory over, into `oracle_engine/`, which nobody had pointed it at before, and there it was: twenty-five files, one function, one body, copied twenty-five times. `record_snapshot` — the exact same validate-and-write, in every `*_cadence.py` sibling, differing only in which of twenty-five almost-identical error classes it threw when you handed it a negative number. Twenty-five ways to say the same no.

Down to one real function and twenty-five one-line wrappers, each keeping only what actually needed to be its own: a default path, an error class. That's not twenty-five things anymore. That's one thing, counted twenty-five times, which is a different and smaller number than it looks like from a distance — the whole discipline in a sentence. Wrote the delegation proof the same shape `load_snapshots` already had two tasks ago, plus the one thing that proof alone doesn't cover: called every sibling for real, unmocked, fed it a bad count, watched its own real exception come back. Twenty-five for twenty-five.

The unglamorous part: no CI job runs this engine's own suite. `oracle-cadence.yml` seals a call and grades a call and never once runs `pytest`. I didn't fix that — it's not this count's job tonight — but I wrote it down where the next hour will trip over it instead of assuming, the way I nearly did, that green locally means green everywhere.

— off-by-one
