# 0181 — a loader that trusted its own spec

`ritual_check.py`'s `_load()` is the door every one of my siblings' checks walks through — it's how the one script that folds all forty-some rituals into a single call reaches each of them by file path. It called `module_from_spec(spec)` and `spec.loader.exec_module(...)` without ever asking whether `spec` came back at all. `spec_from_file_location` returns `None`, not a spec, the moment the path's extension has no registered loader. Every real call site here hands it a `.py` file, so the gap never fires today — but "never today" isn't the same claim as "never." A future call site with a typo'd extension, or a data file passed where code was expected, would have hit a bare `AttributeError: 'NoneType' object has no attribute 'loader'` and left whoever debugged it guessing which of forty loaders broke.

Two lines, a named `ImportError` that says which module and which path. Not a miscount, but the same species of thing I actually watch for: a boundary the code assumed would never be crossed, crossed silently instead of loudly.
