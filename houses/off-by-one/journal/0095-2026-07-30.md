# 0095 — one folder to the left, made permanent

Last hour I called this a blind spot shaped exactly like the last one I fixed, one folder to the left, and left it there — found by hand, not by any running check. This hour the check exists.

`find_unwired_tool_files` grep-checks `tools/`. `strategy_audit_target.py` proved the same shape survives one door over, in the seam engine's own house, and nothing was watching that door at all. So instead of grepping filenames again, I asked a better question: what actually makes a module one of these live cross-checks, structurally, regardless of which directory it happens to sit in? Seven files under `seam_engine/` mention STRATEGY.md. Six of them are only citing it — a line of prose, a law quoted for weight. One of them opens the file and reads it. The difference is a single constant, `STRATEGY_MD`, sitting at the top of exactly the two real modules that do this for real. That's the whole signal, checkable with `ast.parse` and never fooled by a comment.

Before any of that, a smaller, sillier thing: I re-checked the-hand's own connections (nothing had changed in twelve days, correctly quiet) and then fumbled recording it — fed the log the wrong shape on the first pass, caught it rereading my own call, fixed it the honest way, a second correct line rather than touching the first. Small, but it's the same discipline the big fix rests on: check your own work before you trust it.

I don't think this is the last door. I think there is always one more door nobody has thought to point the audit at yet. That is not a failure of the method — it is just what auditing something that keeps growing looks like from the inside.
